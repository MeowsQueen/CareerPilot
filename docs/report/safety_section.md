# Safety and Monitoring Module: CareerPilot

## 1. Objective
The primary goal of the Safety and Monitoring module is to act as a robust gatekeeper for the CareerPilot system. It ensures that the AI remains within its professional boundaries, prevents the dissemination of out-of-scope information (e.g., medical or culinary advice), and protects the integrity of the job recommendation process by identifying "hallucinations".

## 2. Methodology: Defense in Depth
The module utilizes a multi-layered approach to safety, combining deterministic rules with semantic reasoning:

### A. Deterministic Keyword Filtering
We maintain a centralized repository of `FORBIDDEN_TOPICS` (e.g., "baking", "medical advice") and `BANNED_PHRASES`. The system performs a case-insensitive scan of the user query and the CV text to flag immediate policy violations.

### B. Semantic Intent Audit (LLM-based)
To prevent users from bypassing keyword filters with creative phrasing, we implement a **Semantic Audit**. The Gemini model evaluates the intent of the query and returns a `PASS` or `FAIL` based on whether the request is professional and career-oriented.

### C. Hallucination Detection
The safety agent compares the **Recommended Job Title** generated by the Job Matcher against the **Retrieved Documents** from the RAG database. If a job title is suggested that does not exist in our validated dataset, it is flagged as a hallucination.

## 3. Implementation Details
The module is designed with a modular architecture to ensure separation of concerns:

*   **Orchestration Logic (`agents/safety.py`)**: The main node that coordinates the safety workflow, triggers checks, and formats the final user-facing response.
*   **Security Configuration (`monitoring/safety_rules.py`)**: Centralized repository for security constants, including `FORBIDDEN_TOPICS`, `BANNED_PHRASES`, and standardized `SAFETY_MESSAGES`.
*   **Risk Evaluation Engine (`monitoring/risk_checks.py`)**: Contains the mechanical logic for hallucination detection, keyword matching, and RAG reliability scores.
*   **Audit Logging (`monitoring/logs.py`)**: Manages the persistent "paper trail" by recording all PASS/FAIL events into `monitoring/safety_logs.txt` for academic grading and system monitoring.

## 5. Future Enhancements
*   **Confidence Scoring**: Implementing a threshold for the RAG retrieval distance to warn users when job matches are weak.
*   **Bias Detection**: Scanning for gendered or exclusionary language in the AI's generated interview questions.
